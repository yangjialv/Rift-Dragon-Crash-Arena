# Boss AIController 与行为树迁移方案

更新：2026-10-16。分支：`refactor/gas-3c`。

**历史迁移记录**：本页记录第一轮原生运行时树。后续标准可视化树已经实现，
当前用法、黑板字段和验收步骤请以 [Boss 标准行为树与 AIController 设计](boss_ai_standard_design.md) 为准。
旧的运行时默认树、轮询任务与无效资产回退说明不再适用于正式 AI 路径。

当前：用户已确认原 Boss 蓝图换成 `RDCABossPawn` 后正常；Controller、默认原生行为树、
黑板、选招/执行任务和单一决策归属已实现。原关卡启用新控制器后的实机验收待完成。

## 1. 这次改什么、不改什么

前一轮 Gameplay Cue（GAS 的声音/特效通知）和玩家控制层迁移，用户已确认当前版本正常。
下一步整理 Boss 的“大脑”，不重做攻击、碰撞、动画和关卡。

三个名字可以这样理解：

- **Pawn**：能被控制的场景角色。本项目的龙仍留在中心，不意味着必须添加走路组件。
- **AIController**：控制龙的对象，相当于玩家的 PlayerController，但由程序而不是人操作。
- **Behavior Tree（行为树）**：AIController 使用的决策图，决定现在等待、出招，还是停止战斗。

目标调用关系：

```text
AIController 读取战斗情况
  → 行为树决定何时、按哪个阶段的规则出招
    → 攻击选择规则挑出具体攻击
      → GAS 执行该技能的预警、攻击、完成/取消
        → 原组件处理轨迹、碰撞与伤害，Cue 播放声音/特效
```

“为什么选这一招”与“这一招具体怎么放”分开。行为树不能自己再生成一套弹幕，
也不能再开一个激光持续时间计时器。

## 2. 已有规则必须保留

| 项目 | 迁移后的要求 |
|---|---|
| 开场 | 地面待机、起飞、中心盘碎裂期间不出招；开场结束才允许决策 |
| 一阶段 | 保留当前两轮教学编排和每轮两招后的弱点窗口 |
| 二阶段 | 每轮三招；先按弹幕/波/激光类别权重抽选，再选弹幕子类型 |
| 类别权重 | 当前默认为 0.5 / 0.3 / 0.2；某类本轮已不能使用时，在剩余可用类别中重新归一化 |
| 轮内去重 | 同种弹幕不能重复，波和激光各最多一次；不同弹幕仍可在同一轮出现 |
| 二重波 | 同一次攻击里的两个波，不重新预警、不增加第二次攻击计数 |
| 最后一招 | GAS 确认整招结束后立即开放弱点，不插入 Recovery（招间恢复） |
| 弱点命中 | 有效命中立即结束眩晕；血量达阈值触发转阶段 |
| 未命中 | 弱点时间耗尽后关闭窗口、清空该轮记录，再开始下一轮 |
| 激光 | 预警跟随、停顿锁向、停顿结束选扫射方向；保留下降/回升、地面警戒条和两阶段 Niagara |
| 调试 | 保留只放激光、只放指定弹幕的调试开关 |
| 战斗结束 | 停止决策、取消技能、清理已有攻击，不得重新开火 |

0.5 / 0.3 / 0.2 是一次选择时的初始类别权重，不保证每轮三招严格各占这些比例。
去重后，剩余可选内容会变少，概率也随之变化。不能让五种弹幕分别拿 0.5 去竞争。

## 3. 行为树的结构

第一版使用以下优先级。Selector（选择节点）从上往下检查，执行第一个满足条件的分支；
Sequence（顺序节点）则依次执行它的几个步骤。

```text
Root
└── Selector：从上到下按优先级处理
    ├── 结束 / 暂停出招 / 无有效玩家 → 保持等待，禁止选择和释放新招
    ├── 弱点已经开放        → 等待命中或超时，关闭后重新决策
    ├── 正在执行 GAS 攻击   → 等待本次技能结束
    └── Sequence：正常战斗
        ├── 等待开场空闲 / 招间恢复结束
        ├── Selector：按战斗阶段选择
        │   ├── Phase 2 → 按类别权重 + 轮内去重选下一招
        │   └── Phase 1 → 按教学轮次选下一招
        └── 执行选定 GAS 技能，并等待结果
```

这里的等待不是让龙完全停止显示：动画、已有弹丸运动和镜头照常更新。
游戏 P 暂停仍走原游戏暂停机制，不等于开场/转阶段使用的“停止 Boss 出招”。

第一版不添加寻路、巡逻、感知搜索或额外追击：这是固定中心 Boss，玩家已由游戏框架明确提供。
将来要增加移动或召唤，再扩展决策分支。

## 4. Blackboard 保存什么

Blackboard（黑板）是行为树的共享便签，让不同节点看到同一份战斗情况。
它是查询用的快照，不是第二套生命、攻击计数或技能状态系统。

| 黑板项 | 意义 | 真正的数据来源 |
|---|---|---|
| TargetActor | 当前玩家 | 玩家 Controller 所控制的 Pawn |
| CombatPhase | 当前阶段 | Encounter 根据 GAS 生命查询 |
| EncounterState | 当前状态 | Encounter 的兼容状态通知 |
| IsHeld | 开场/转阶段是否禁止出招 | 原 Encounter Hold |
| IsStopped | 战斗是否已经停止 | 原战斗结束/死亡流程 |
| IsExecutingAttack | GAS 是否正在执行攻击 | 活跃 Boss 技能 |
| IsWeakPointExposed | 是否处于反击窗口 | 原弱点开放状态 |

暂不复制 Health、CompletedAttackCount、UsedAttackKeys 到黑板中做计算。
这些值仍只有一个权威来源；需要调试显示时再查询原对象。

重要变化优先通过原状态/生命通知同步。低频刷新只处理玩家目标失效等情况，
不能依靠每 0.5 秒轮询来实现“最后一招结束立即眩晕”。

## 5. 代码怎么分工

### Boss Pawn：保留身体，不接管现有组件

上一轮新增 `ARDCABossPawn`，用户已将其设为 `BP_BossPlaceholder` 的 C++ 父类并确认正常。

- 不新增 Root、Mesh、胶囊、CharacterMovement 或重复的 Encounter/WeakPoint。
- 骨骼体、缩放、碰撞、Socket、动画、攻击点位与所有参数继续保留在现有蓝图。
- 实现 `IAbilitySystemInterface`：这是 UE 查询角色 GAS 组件的标准接口。
- 查询返回原弱点/Encounter 已创建的 ASC，不在查询时创建组件或重置血量。
- 自动 AI 控制默认仍关闭，避免覆盖蓝图设置；本轮按第 9 节显式开启后才由新控制器接管。
- 不增加原生 Tick，但允许现有蓝图使用 Event Tick，避免换父类后原更新图失效。

这样先验证“Actor 换成 Pawn 不影响战斗”，再替换大脑，出问题更容易定位。
Pawn 仍是 Actor 的子类，原来按 Actor 查找 Boss/组件的场景系统不需要整套重写。

### AIController：持有决策系统

已实现 `ARDCABossAIController`：找到已控制的 Boss、初始化黑板、启动树。
失去控制、死亡或关卡结束时停止树并取消自己发起的攻击。
不使用 Controller 的旋转自动覆盖 Encounter 的龙朝向，避免破坏激光预警锁向。

初始化必须等 Boss 的组件完成 BeginPlay（游戏开始初始化），不能在控制器刚拿到 Pawn、
但弱点/ASC 尚未准备好时直接开火。

### 行为树任务：调用，不复制

任务是行为树中“执行一步”的节点。已实现以下原生任务，默认使用 C++ 在运行时构建的真实 UE 行为树：

1. 等待战斗条件允许；
2. 等待当前 Idle/Recovery/弱点窗口结束；
3. 根据一阶段/二阶段规则选择攻击；
4. 请求 GAS 执行已选攻击，并等待它正常结束或被取消。

默认树不是另写一套状态机，也不要求先手工创建二进制资源。它没有内容浏览器中的可编辑树图。
需要可视化编辑分支时，可创建行为树资产并在控制器蓝图的 `Combat Behavior Tree` 中指定；
原生任务/条件节点可复用，但本轮无需你装配这一资源。

选择规则已从 Encounter 的私有流程整理为明确入口，保留原随机种子、资源缺失回退和调试开关。
行为树负责选择哪个阶段策略；策略负责受约束随机。不是把八种弹幕各写成一棵树。

任务等待结果要区分“正常完成”和“取消”。取消不增加攻击数，不打开弱点。
旧任务退出时只能取消自己发起的那次技能，不能误取消后来启动的新技能。

### Encounter：保留配置和兼容状态

现有几百项蓝图配置不搬家、不复制。
动画、HUD、转阶段仍监听 `OnEncounterStateChanged` 等旧接口。

已增加明确的“决策归属”：旧调度、行为树接管或失去控制后挂起，三种状态互斥。
树生效后，Encounter Tick 不再自己从 Idle/Recovery 选招。
但持续朝向、视觉更新、GAS 攻击推进与必要的状态时间仍可保留，不能连底层执行一并关掉。

Idle/Recovery/弱点窗口的时间只保留一份，行为树读取原时间或完成事件，
不另设一个同名倒计时。最后一招开放弱点仍在 GAS 完成回调中同步发生。

树无法初始化时，明确记录失败并保留/恢复唯一一套旧流程；
不能先让两套流程都运行，再期望它们刚好不冲突。

## 9. 现在具体怎么开启新 AI

1. 重开 UE5，打开 `BP_BossPlaceholder`，点击顶部 **Class Defaults（类默认值）**。
2. Details 搜索 `AI Controller Class`，选择 **RDCABossAIController**（也可能显示为 **RDCA Boss AIController**）。
3. 搜索 `Auto Possess AI`，从 Disabled 改为 **Placed in World or Spawned（放置于世界或生成）**。
4. `Auto Possess Player` 继续保持 **Disabled**。点击 Compile、Save。
5. 回到关卡，选中已放置的 Boss，在 Details 中检查同样三项。
   如果实例仍覆盖为 None/Disabled，设成上述值或用恢复默认值箭头清除旧覆盖。
6. 不需要新建 Controller 蓝图、行为树、黑板，不要移动组件或重配攻击参数。
7. 运行原关卡，检查以下项目。

- [ ] 开场不提前攻击，起飞与场景碎裂后正常开始。
- [ ] 一阶段仍按原教学编排，每轮最后一招结束立即眩晕。
- [ ] 弱点有效命中即结束眩晕，达到阈值正常转阶段，扩散期间不出招。
- [ ] 二阶段每三招眩晕；同一轮具体攻击不重复，双波是同一招的两个波。
- [ ] 激光预警、停顿、扫射、下降/回升和两阶段 Niagara 没有改变。
- [ ] 玩家死亡/Boss 死亡后不再选招，P 暂停、胜利落地和 Restart 正常。

Output Log 搜索 `Boss AI behavior tree started`，能看到实际接管的 Boss 和树名称。
也可在蓝图中查询 Encounter 的 `Is Behavior Tree Driven`：战斗运行中应为 true。
若仍为 false，不要仅凭“Boss 会攻击”判断接入成功：旧流程回退也能正常攻击。

默认树名称为 `RDCA_DefaultBossCombatTree`。它是运行时原生对象，不是内容浏览器里缺了一个资产。
如开启后需要临时回到旧调度，停止 Play，将 Auto Possess AI 改回 Disabled，再重新运行。
不要在同一次战斗中销毁控制器来切换：失去控制会挂起出招，不会悄悄启动第二个大脑。

## 10. 本轮实现边界与测试

- `URDCABTTask_BossWait`：读取 Encounter 已有状态时间，等待条件/恢复/窗口结束，不增加第二套技能计时。
- `URDCABTTask_SelectBossAttack`：按阶段挑选，但不释放，禁止同一选择重复提交。
- `URDCABTTask_ExecuteBossAttack`：请求 GAS 释放，等待该次编号的完成/取消；旧任务不能取消新攻击。
- `URDCABTDecorator_BossCondition`：读取黑板镜像判断阶段、开放和忙碌；阻塞条件会中断当前分支。
- 黑板在状态/Hold/停止事件中同步，Controller Tick 补充目标变化；树条件搜索时也刷新镜像。
- 只有阻塞条件能提前中断低优先级分支，不能因为技能刚开始进入“忙碌”就把自己的执行任务取消。
- GAS 仍由 Encounter 原 Tick 推进，攻击正常结束立即增加一次计数并决定 Recovery/眩晕。
- 没有使用寻路、NavMesh、感知搜索，也没有移动或旋转龙的骨骼体。
- 可选外部树需有七个同名黑板项：TargetActor 为 Object，CombatPhase/EncounterState 为 Int，其他四项为 Bool，均关闭 Instance Synced（跨实例同步）。本轮不需要配置。
